# Zelotes C-18 — конфигурация как код

Репозиторий с воспроизводимой настройкой мыши **Zelotes C-18** (SOAI C18,
VID:PID `12C9:2003`) под Windows: подсветка, DPI, частота опроса и активный
профиль.

Одна команда приводит устройство к состоянию из
[`config/default.toml`](config/default.toml). Вендорский драйвер, Zadig/WinUSB
и права администратора не нужны — используется штатный вендорский
HID-интерфейс мыши.

> Клавиатура AJAZZ AK680 MAX живёт в отдельном репозитории:
> [`jazz-crab/ak680-max`](https://github.com/jazz-crab/ak680-max).

## Главное: выключить подсветку

```powershell
py -3 -m pip install -e .
c18 off            # dry-run: показать payload
c18 off --yes      # записать mode 0x00
```

`off` выключает подсветку и не трогает частоту опроса. Важно: подсветка и DPI
хранятся в одном 64-байтовом пакете, поэтому `off` записывает и DPI-байты —
берёт их из конфига. По умолчанию там заводские значения, так что DPI не
меняется.

Если подсветка осталась, значит активен второй профиль — попробуй:

```powershell
c18 off --yes --profile 1
c18 off --yes --profile 2
```

По умолчанию конфиг пишет в оба профиля и оставляет активным профиль 1: у
мыши нет чтения активного профиля, а подсветка хранится per-profile.

> Проверено на этой мыши (Windows 11, `12C9:2003`): `c18 off --yes` с записью
> в профили 1 и 2 **полностью гасит декоративную подсветку**. DPI-байты
> остаются заводскими (`22 39 5c d0 f3`), частота опроса не меняется.

## Индикация DPI

У C-18 есть отдельные светодиоды, показывающие активную DPI-стадию. Это
аппаратная индикация: вендорская утилита не даёт её выключить, и в
HID-протоколе нет ни команды, ни поля для неё. `off` гасит декоративную
подсветку, но не эти индикаторы — проверено на железе.

Что можно попробовать (вне протокола):

- удержать кнопку DPI 3–5 секунд — на части мышей Zelotes так переключается
  подсветка (поведение зависит от прошивки);
- проверить, нет ли на нижней панели отдельного выключателя подсветки;
- если ничего не помогает — остаётся физически закрыть или отключить
  светодиоды; программного пути нет.

## Кнопки

В мыши 11 кнопок. Таблица кнопок пишется целиком (чтения нет), поэтому конфиг
описывает все нужные слоты, а неперечисленные остаются заводскими. Формат
действия — строка:

```toml
[buttons]
4 = "shortcut:ctrl+v"
5 = "shortcut:ctrl+c"
6 = "media:play-pause"
7 = "shortcut:alt+tab"
8 = "key:enter"
10 = "shortcut:win+shift+s"
11 = "key:printscreen"
```

Поддерживаются `click:*`, `key:*`, `shortcut:<мод>+<клавиша>`, `media:*`,
`dpi:*`, `profile:*` и `none`. Полный список форм — в комментариях
[`config/default.toml`](config/default.toml).

Текущий пресет:

| # | Действие |
|---|---|
| 1–3 | left / menu / middle click |
| 4 | Paste (Ctrl+V) |
| 5 | Copy (Ctrl+C) |
| 6 | Play/Pause |
| 7 | Alt+Tab |
| 8 | Enter |
| 9 | Ctrl+Z |
| 10 | скриншот области (Win+Shift+S) |
| 11 | весь экран (PrintScreen) |

> На Windows 11 PrintScreen по умолчанию может открывать «Ножницы» — тогда
> обе кнопки делают скриншот области. Отключи это в
> Параметры → Специальные возможности → Клавиатура, если нужен именно весь
> экран. Альтернатива — `shortcut:win+printscreen` (сохраняет файл в
> `Изображения\Снимки экрана`).

## Win+Scroll → громкость

Прошивкой это не сделать, и вот почему:

- колесо — не кнопка, а отдельная HID-ось; в таблице кнопок для неё нет слота;
- мышь не знает, зажат ли Win **на клавиатуре** — модификаторы это состояние
  хоста, устройство его не видит. Поэтому «Win+Scroll» не может быть зашит в
  мышь: она не может отличить скролл с Win от обычного;
- у клавиатур с колесом громкости энкодер распаян как отдельный
  consumer-control и всегда шлёт Volume Up/Down — это не «колесо с
  модификатором».

Рабочий путь — хост-хук. AHK не обязателен: в репозитории есть скрипт на
встроенном PowerShell, без установки чего-либо —
[`tools/win-scroll-volume.ps1`](tools/win-scroll-volume.ps1).

Запуск без окна:

```powershell
powershell.exe -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass `
  -File "C:\Users\JazzCrab\zelotes-c18\tools\win-scroll-volume.ps1"
```

Автозапуск: `Win+R` → `shell:startup` → ярлык с этой командой.

Скрипт ставит низкоуровневый хук мыши (`WH_MOUSE_LL` через встроенный .NET) и
шлёт `VK_VOLUME_UP` / `VK_VOLUME_DOWN` только когда зажат Win. Обычный скролл
не трогает: без Win событие уходит дальше.

Тот же хук есть в виде AHK-скрипта
[`tools/win-scroll-volume.ahk`](tools/win-scroll-volume.ahk) — он короче и
чуть легче, но требует установки [AutoHotkey v2](https://www.autohotkey.com/).

Ограничения у обоих одинаковые: игры с raw input и окна, запущенные от
администратора, хоткей не увидят (если хук не запущен elevated). Ничего не
прошивается; откат — закрыть скрипт.

## Что настраивается

| Слой | Что задаётся | Где в конфиге |
|---|---|---|
| Профили | в какие профили писать, какой оставить активным | `[profile]` |
| Подсветка | режим, цвет, яркость, скорость эффекта | `[lighting]` |
| DPI | 5 стадий и активная стадия | `[dpi]` |
| Кнопки | действие для каждого из 11 слотов | `[buttons]` |
| Polling | 125/250/500/1000 Гц | `[polling]` |

Режимы подсветки: `off`, `static`, `breathing`, `neon`, `wave`, `flowing`.
У `static` цвет — один из аппаратных пресетов (`red`, `green`, `blue`,
`yellow`, `purple`, `cyan`, `white`), потому что железо хранит бинарную маску
каналов, а не произвольный RGB.

## Требования

- Windows 10/11 x64 (проверено на Windows; код использует hidapi и
  потенциально переносим, но другие ОС пока не тестировались).
- Python 3.11+.
- Мышь подключена проводом.
- Вендорская утилита SOAI/Zelotes закрыта.

## Установка

```powershell
git clone https://github.com/jazz-crab/zelotes-c18.git
cd zelotes-c18
py -3 -m pip install -e .
```

Если команда `c18` не появилась в `PATH`, используй `py -3 -m zelotes_c18`.

## Быстрый старт

```powershell
c18 status          # интерфейс + конфиг, ничего не пишет
c18 probe           # report descriptor, длины отчётов, GET_REPORT
c18 apply           # dry-run: показать план
c18 apply --yes     # записать конфиг
c18 off             # dry-run: только выключение подсветки
c18 off --yes       # выключить подсветку
```

`apply` и `off` без `--yes` **ничего не пишут**. Это осознанное правило:
сначала смотрим план и payload, потом заливаем.

Проверки без устройства:

```powershell
python -m unittest discover -s tests
```

## Команды

| Команда | Что делает |
|---|---|
| `status` | находит вендорский интерфейс, печатает конфиг и `GET_REPORT` |
| `probe` | подробная read-only диагностика: descriptor, длины, счётчик |
| `apply [--yes] [--no-polling]` | приводит мышь к конфигу |
| `off [--yes]` | выключает подсветку (LED mode `0x00`) |

Общие флаги: `--config PATH` (или `ZELOTES_C18_CONFIG`), `--profile 1|2|both`,
`--select 1|2`.

## Конфиг — это намерение, а не снимок

`config/default.toml` описывает **что должно получиться**, а не сырые байты.
Протокол мыши write-only: LED, DPI, кнопки и профили нельзя прочитать обратно.
`GET_REPORT` отдаёт только счётчик/эхо команд. Поэтому:

- **backup устройства невозможен**;
- **verify невозможен**;
- откат — это повторный `apply` предыдущего конфига из git или заводские
  настройки через вендорскую утилиту.

Подсветка и DPI при этом не независимы: они живут в одном 64-байтовом пакете,
и устройство применяет его целиком. Поэтому конфиг всегда задаёт обе
подсистемы, а флагов «не трогать подсветку»/«не трогать DPI» нет — это было бы
иллюзией.

Это отличие от клавиатуры, где состояние читается и проверяется побайтово.
Подробный регламент — в [`PROVISIONING.md`](PROVISIONING.md).

## Как это работает

1. `begin` — фиксированный 8-байтовый пакет `01 88 00 00 00 00 00 76`.
2. `0C <profile> 80`, затем 64-байтовый праймер и единый пакет, в котором
   лежат и подсветка, и пять DPI-стадий.
3. `0D <profile> 80` и 64-байтовая таблица кнопок (без праймера).
4. Для polling — `03 <profile> <interval>`.
5. `commit` — `02 <profile> ...`; он же выбирает активный профиль.

Все 8-байтовые команды имеют checksum `0xFF - sum(byte[0..6])`; сумма всех
восьми байт всегда `0xFF`.

## Ограничения

- Только Windows протестирована.
- Нет чтения состояния: нельзя проверить, что реально залито.
- `static`-цвета — только 8 аппаратных пресетов, не произвольный RGB.
- Кнопки поддерживают click/key/shortcut/media/dpi/profile; макросы и
  Armoury-пресеты не настраиваются.
- DPI-калибровка снята с этой модели; на другой мыши её нужно пересчитывать.
- Подсветка, DPI и кнопки per-profile; по умолчанию пишем в оба профиля.
- Индикация DPI (четыре светодиода стадий) — аппаратная, протоколом не
  управляется.
- Win+Scroll → громкость — только софтом (AutoHotkey), не прошивкой.
